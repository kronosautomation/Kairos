# A2A: Kairos.A2A and Kairos.Agents.A2aClient, design decisions and open items (Milestone 5)

Written 25 Oct 2026. Internal. Placement decided by Aaron: protocol and client in Kairos (Apache), hosted server in Kairos.Commercial
(`docs/REPO-LAYOUT.md`). Built on the official `A2A` / `A2A.AspNetCore` NuGet packages, **1.0.0-preview3**, pinned (a prerelease: the packages
here carry `VersionSuffix=preview` until the SDK is stable).

## SDK facts (read from the packages and by running them)

- Types for protocol 1.0: `AgentCard` (with `Signatures`: `AgentCardSignature { Protected, Signature, Header }`), `AgentTask`, `TaskState`
  (Submitted, Working, Completed, Failed, Canceled, InputRequired, Rejected, AuthRequired), `Message`, `Part`, `Artifact`.
- Client: `IA2AClient` / `A2AClient`, `A2AClientFactory.Create(card, http, options)`, `SendMessageConfiguration.ReturnImmediately`.
- Server: `IA2ARequestHandler` (the request surface), `A2AServer` (handler + `ITaskStore` + `IAgentHandler`), `MapA2A`, `MapWellKnownAgentCard`.
  `ITaskStore` includes `ListTasksAsync`, which Kairos cannot serve without a listing API on `IKairosStore` (same gap as MCP `list_runs`).
- **The SDK ships no card signing or verification**, only the signature type. That is what `Kairos.A2A` adds.

## Decisions

1. **Signing follows the A2A text:** JWS over RFC 8785 canonical JSON of the card without `signatures`; protected header `{alg, kid, typ}`.
   Only ES256 is produced and accepted, because the verifier then needs just a public key and there is no algorithm negotiation to attack.
2. **Verification is by trusted key id only.** No `jku` fetch (SSRF, and it would make the card vouch for itself), no `x5c`, unknown header
   fields refused. A card with several signatures is accepted if any one verifies with a trusted key.
3. **Cards from elsewhere are verified as received** (`VerifyJson`). Re-serializing through the SDK drops fields it does not model, which
   breaks a valid signature (pinned by a test); the connector therefore fetches the raw bytes itself and verifies before deserializing.
4. **The JCS number formatter is our own** (BCL has none). Vectors from RFC 8785 are in the tests; cards rarely contain non-integers.
5. **A run is the task** (`KairosA2aTasks`, mirror of the MCP attached task): state is projected from history on each read, nothing is stored
   twice. `SagaCancelledException` maps to `canceled`, `ApprovalRejectedException` to `rejected` (A2A has the state), everything else to `failed`.
   The same id rules as the MCP task store (tenant/namespace bound, optional HMAC).
6. **Client steps mirror the MCP client:** the send step records the answer or a task id; polls are separate steps separated by durable timers
   with a growing wait; policy is evaluated in the send step (agents are `a2a.<name>`, side-effecting unless declared read-only) with the same
   two-call approval pattern. The message id is the activity idempotency key.
7. **`ReturnImmediately = true`** always, so a slow agent never holds a worker; the cost is one extra round trip for fast agents that return a
   message anyway (they answer in the first reply, so there is none in practice).

8. **Signed cards are required by default (review fix).** `A2aAgentConnector.RequireSignedCard` is true unless `AllowUnsignedCard()` is called on that
   connector; `AddAgent(name, uri, http, verifier)` no longer accepts a null verifier (the exception names the opt-out). A connector with neither a verifier
   nor the opt-out refuses before fetching anything. With the opt-out, an unsigned card is accepted but a card whose signature fails is still refused (unsigned is
   unvouched, a failed signature is a forgery). The opt-out is per agent and in code on purpose: it shows up in review. Breaking change from the first cut,
   made while the packages are preview.
9. **Cancelling the workflow cancels the remote task in the rollback (review fix).** `CallA2aAgentAsync` registers an undo (`kairos.a2a.cancel`) as soon as the
   remote task id is known and discards it when the task ends by itself; it races each poll wait against `saga.WhenCancelled`, so a cancel is noticed at once. New
   saga primitives in `Kairos.Agents`: `Compensate` returns a `SagaCompensationHandle` (`Discard()`), `ISaga.WhenCancelled`, `IAgentContext.CurrentSaga`.
   Cancelling an ended or unknown remote task is not an error (`TaskNotCancelable` / `TaskNotFound` are swallowed), so the undo cannot be retried 100 times
   against a task that finished. A saga bug found on the way: an inner saga ending cleared the cancel-awareness of the outer one; fixed and tested.
   An input-required task keeps its undo (it is alive); continuing it registers a second, harmless one.

## Open items

- **No streaming and no push notifications** on the client: polling only. A2A streaming could shorten latency; durability of a stream is a
  design question of its own (resume tokens).
- **Remote cancellation when the answer to the first message is lost** before its task id is known: nothing recorded the id, so nothing can be cancelled.
  The message id is stable, so the server de-duplicates, but the task keeps running until the server's own timeout. The same gap exists for the MCP client,
  which also has no cancel-on-rollback yet (the new saga primitives make it a small change).
- **`ListTasks` / `ITaskStore`:** not provided for hosted agents until the store has a listing API.
- **Authentication of the outbound call** (OAuth, API keys from the card's security schemes) is the `HttpClient` the caller supplies; the
  client does not negotiate a scheme from the card.
- **Card refresh:** cached for ten minutes per connector; a key rotation by the publisher needs the verifier's trusted set updated by the caller.
- **Conformance:** the A2A conformance tooling has not been run; the SDK round trips here are ours.
- **AOT:** not enabled for these two packages (the SDK is not annotated).
